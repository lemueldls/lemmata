# Geometry core

`lemmata-geom` holds the primitives that glyph definitions call. Two of them are ported and verified. Details of the Spiro provenance are in `docs/spiro.md`.

## Spiro

`crates/lemmata-geom/src/spiro.rs` evaluates spiro curves. Two checks cover it:

- `tests/spiro_golden.rs` replays `corpus/spiro-knots.json` against npm `spiro` output and matches within 1e-9 font units.
- `tests/glyph_spiro.rs` replays 24 knot sets captured from a real Iosevka build against the Bezier output that build produced. Worst deviation is 0.85 font units, under the 1 unit budget. The residual is mostly Iosevka's own Bezier conversion, since our evaluation subdivides more finely.

## Overlap removal

`crates/lemmata-geom/src/boolean.rs` wraps linesweeper for union, intersection and self-overlap removal on kurbo paths. Iosevka uses typo-geom on an integer grid for the same job, so the two agree within that grid's resolution rather than exactly.

## Not ported yet

- The contrast pen expander (`spiro-expand.mjs`, `spiro-pen-expand.mjs`) that turns a skeleton with tension into two offset sides. This is the most-used path after plain Spiro.
- The stroke expander (`stroke.mjs` plus `OffsetCurve` and `RoundCapCurve` from `curve-util.mjs`), which offsets a contour and unions the sides.
- Quadratic conversion (`quadify.mjs`) for TrueType output.

Each has a matching upstream module, so the differential approach used for Spiro and the captured skeleton corpus extends to them.

## Captured fixtures

`corpus/glyph-spiro.json` and `golden/glyph-spiro.json` came from the same instrumented build described in `docs/glyph-strategy.md`. They are regenerated by re-running the counter wrapper and capture, not by a checked-in script.
